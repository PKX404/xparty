# XParty social and provider redesign

Requested direction: dark immersive interface; member photos, biographies, interests and likes/dislikes; mutual friends; shared watching history and time together; eventual coverage of every service Rave offers. Supabase is already configured according to the owner; its configuration and schema have not been inspected in this session.

## Implemented in this revision

- Dark violet surfaces, responsive provider cards, member chips and accessible profile dialogs.
- Editable device profiles: display name, resized JPEG avatar, biography, up to eight interests, likes and dislikes. Saving shares the profile in joined rooms and retains it on this device. Signed-in users also save those fields to their existing Supabase profile after the additive migration.
- Any member can open another member's profile. Self-owned room profile updates are bounded and cannot supply account identity or modify another member.
- Room-scoped mutual friends and shared watching history, disclosed only to the requesting participant. Watching counts only while both online devices report visible playback of the current shared source, with an eight-second heartbeat expiry. Twenty recent sources per pair are retained. These are device-reported room statistics, not independently verified account analytics.
- Account friend profile cards and a database function that returns only the mutual intersection to an accepted friend. No full private friendship graph is returned.
- Vimeo through its official browser Player SDK, and public HTTPS MP4/WebM sources through the existing video element; host approval, buffering, seeks, volume and source switching use the existing room controls. Multi-provider queue/next/previous retain YouTube compatibility.
- Spatial GPU video blur behind chat: two Gaussian passes, final saturation and highlight grading, existing device on/off preference. Four samples per second; reduced-motion/paused state retains a still image. YouTube still needs opt-in exact-current-tab capture for live pixels; thumbnails are the fallback.

Static APK corroboration: the supplied Rave tree contains EnabledProviders.smali fields for Amazon, DiscoMax, Disney, Drive and Netflix; assets contain Amazon/Netflix/Disney/Google Drive/Google Photos/Crunchyroll/Pluto/X scripts. VK and Rutube assets were also found, but their current availability was not established. Asset presence alone does not establish working playback. No proprietary provider scripts were copied or executed.

The present XParty Android app loads the hosted web application in a WebView. The provider-specific native playback layer required for broader subscription integration does not exist here. Loading arbitrary provider sites in an iframe or adding their logos would not complete these integrations. Choose and validate each service's supported playback route before advertising it.

## Database and account work

Apply accounts/redesign-migration.sql after the existing schema. It adds profile text/tag fields and an authenticated mutual-friend function. Existing profile/photo/friendship data is preserved. The migration has not been applied or validated against the live database. The owner connected Supabase under PKX404 and supplied project gydhasaztdanfidrysfp, which already has an account schema. Plugin discovery confirms installation, but this running session still exposes no Supabase SQL/project tools. Inspect the existing schema before migration; see AUTH-PROTECTED-ROUTES.md.

Cross-room durable shared watching history remains unimplemented. It needs verified linkage between room sessions and authenticated account IDs, consent/visibility preferences, durable deduplicated watch records, account deletion cascades and retention limits. Current guest room IDs must not be trusted as account identities. Do not label room-scoped numbers as lifetime friendship statistics. This is required remaining work for the requested redesign.
